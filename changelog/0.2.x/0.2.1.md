# 0.2.1 — 2026-11-19

## Changed

- **`seerr_get_media` and `seerr_request_media` call `openRequest` / `existingRequest` the latest request** ([#16](https://github.com/cyanheads/seerr-mcp-server/issues/16)). The `content[]` label reads `**Latest request:**`, and the descriptions say it is the newest request at any quality and in any state; field names and selection are unchanged.
- **`seerr_request_media` `seasons` description:** `"all"` requests every numbered season (1 and up), never season 0; list `0` explicitly for Specials ([#16](https://github.com/cyanheads/seerr-mcp-server/issues/16)).
- **`seerr_search_media` `totalCount`** is described, and rendered in the `content[]` total line, as Seerr's count across movies, TV shows, and people with `mediaType` not applied ([#15](https://github.com/cyanheads/seerr-mcp-server/issues/15)). It always equals Seerr's `totalResults`.
- **`seerr_list_requests`** documents the version limits (`sortDirection: asc` needs Seerr or Jellyseerr 2.2+, `mediaType` `movie`/`tv` needs Seerr or Jellyseerr 2.6+, `deleted` and `completed` need Seerr, Jellyseerr 2.6+, or Overseerr 1.35+) and reports the applied `sortDirection` in `appliedFilters` ([#6](https://github.com/cyanheads/seerr-mcp-server/issues/6), thanks [@ryanmac8](https://github.com/ryanmac8)!).
- **`seerr-guide` skill** 1.0 → 1.1: the `duplicate_request` and `no_seasons_available` refusals, `"all"` never including Specials, and the latest-request wording.
- **Framework sync (mcp-ts-core 0.13.22):** `framework-skills/`, `scripts/`, `changelog/template.md`, and the JWT audience and issuer entries in `.env.example`.

## Fixed

- **`seerr_list_requests` no longer returns HTTP 400 against Overseerr** ([#6](https://github.com/cyanheads/seerr-mcp-server/issues/6), thanks [@ryanmac8](https://github.com/ryanmac8)!). `sortDirection` is sent only for `asc`; every version lists newest first without it.
- **`seerr_list_requests` reports a Seerr HTTP 400 as `unsupported_filter`** with a recovery hint, in place of a generic upstream error.
- **`seerr_request_media` raises `duplicate_request` on Seerr's 409** ([#13](https://github.com/cyanheads/seerr-mcp-server/issues/13)). The reason was declared but never reachable. The message names the blocking request (`#N`, also `existingRequestId`) where Seerr's rule identifies one, a movie's first same-quality request while it is pending, approved, or failed, and never for a TV refusal.
- **`seerr_request_media` raises `no_seasons_available` on Seerr's 202** ([#14](https://github.com/cyanheads/seerr-mcp-server/issues/14)); nothing is created. Also covers `"all"` on a show with no episodes listed yet (Seerr 3.5+). A 2xx answer with no request ID is a `SerializationError`, not a `created` block with an undefined `requestId`.
- **`seerr_request_media` `seasons_required` and `partial_requests_disabled`** carry sentence-case messages of their own, not the contract's `when` text ([#16](https://github.com/cyanheads/seerr-mcp-server/issues/16)).
- **`seerr_get_media` reports a season the show doesn't have as `season_not_found`** (NotFound, with a hint to list the show's seasons); it was a retried `ServiceUnavailable`.
- **`seerr_search_media` no-match notice** no longer echoes the query, so Markdown or line breaks in it can't render as formatting; the `mediaType` hint appears only for `movie` and `tv` ([#17](https://github.com/cyanheads/seerr-mcp-server/issues/17)).
- **Headings in all six tools' `content[]`** parse back to the upstream value when it contains a line break; each break is written as `&#10;` ([#18](https://github.com/cyanheads/seerr-mcp-server/issues/18)).
